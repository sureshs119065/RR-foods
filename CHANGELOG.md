# Changelog

One file for every update made to RR FOODS, newest first. It replaces the separate phase, patch, version and "update notes" files that used to sit in the project root. Statements like "tests were not run" in the original notes described the environment they were packaged in; the current state of verification is in the README.

## 2026-11-14 — Project cleanup and full debug

**Removed**
- The stale nested copy `app/app/` and every root-level file that had been duplicated inside `app/` (Dockerfile, tests, docs, migrations, scripts, md files and so on). The duplicate `app/tests` also stopped pytest from collecting any tests. Size: 16 MB → 8 MB.
- Cloudinary: `migrate_to_cloudinary.py` and `tests/test_cloudinary_storage.py` (not used).
- Dead code that nothing imported: `owner/bundles.py`, `owner/combos.py`, `owner/coupons.py`, `owner/offers.py` and their templates (offer management is Admin-only), `mock_data.py`, the orphan templates `shop/pay.html`, `shop/compare.html`, `account/profile.html`, and the unused assets `site.css`, `rr-foods-mobile-fix.css`, `admin-order-status.js`.
- About 50 markdown and text notes, merged into README.md, this file, `deploy/DEPLOY.md` and `docs/FEATURES-AND-DESIGN.md`. Two generated source-code dumps (about 300 KB) and the 134 KB v25/v26 layout audit were dropped; the audit's findings are summarised under v26 below.

**Fixed**
- `/language` returned a 500 when the request had no referrer (it redirected to a non-existent endpoint).
- The shop's WhatsApp number was read from two different settings: the order flow used `ADMIN_WHATSAPP_NUMBER` but the listing page and Help page read only `WHATSAPP_NUMBER`. All now use one lookup.
- Owner sales charts and the reject-order dialog used inline `<script>` blocks that the site's CSP (`script-src 'self'`) blocks in browsers. They moved to `sales-analytics.js` and `owner.js` (chart data now travels in a JSON data block).
- Race on the first two simultaneous checkouts on a fresh database: both tried to create the delivery-slot settings row and one crashed with a duplicate-key error. Creation is now `INSERT … ON CONFLICT DO NOTHING` followed by the row lock.
- Removed a dead "Payment already received" checkbox in the owner order page that could never render (the live one is in the status form).

**Tests**
- Brought the suite in line with the current app: checkout token and WhatsApp-only payment (shared `checkout_post` helper), 12 products per page, redesigned wording, retired compare page, one consolidated owner order queue, tax-invoice ₹ format, bundle cards on `/offers`, new public pages in the access test, the second lockout layer, admin orders being read-only. The Cloudinary test file was removed. Result: **486 passed**.

**Known gaps found** (not changed): browser push is never sent (see README → Known gaps); `flask db check` reports harmless model/migration drift (see README → Database and migrations). Migrations were verified from an empty database to the single head.

## 2026-11 — Bundles, delivery and WhatsApp ordering

- **WhatsApp-first ordering** replaced cash on delivery and the test payment gateway: one payment method (`upi_manual`), the "Order placed" page that opens WhatsApp with the order written, owner confirmation with an optional "payment received" tick, `set_payment()` (Paid / Not paid with history, audit and notification), a "Not paid only" filter, and `/order-placed/<number>`. The stub `/pay` routes and `pay.html` were removed and `ONLINE_PAYMENT_MODE` is gone. Old COD and online orders still display. WhatsApp Cloud API buttons could later call `change_status` and `set_payment` from a webhook with no other change.
- **Delivery to all of Tamil Nadu:** every pincode 600001–643999 is deliverable by rule (default 3 days, free; `DEFAULT_DELIVERY_DAYS`, `DEFAULT_DELIVERY_FEE`); a `delivery_zones` row overrides one pincode; `add_pincodes.py` manages them. Puducherry and Karaikal share the range and can be disabled per pincode.
- **Bundle edit fix:** the admin and owner layouts defined a menu macro called `item`, hiding the `item` variable the edit forms receive, so edit forms opened empty. The macro is now `navitem`. Also: a failed save keeps what was typed and shows the error, editing no longer changes the slug, editing a bundle that belongs to a festival combo updates the combo, and the old image file is removed when a new one is uploaded.
- **Security and SEO:** Pillow moved to `>=13,<14` (12.x had published advisories); a bundle price saved in the cart is re-checked at checkout (bundle switched off, expired, not started or edited); videos are checked by their real first bytes; Cross-Origin-Opener-Policy and HSTS on HTTPS; `/favicon.ico`; sitemap with `<lastmod>` and About, Bundles and Recipes; Open Graph and Twitter tags and Organization/WebSite JSON-LD; `deploy/nginx-https.conf`; `tests/test_security_part2.py` (45 tests: coupons, stock race, cart tampering, bundle price, IDOR, role separation, lockout, headers, video upload, SEO); `tools/part3_site_checks.sh` and `tools/k6_shop_load.js`.
- **Back-in-stock alerts and white UI (9 Nov, update 2):** "Notify me when available" on sold-out products; in-app notification (and email when mail is on) when stock returns, once per request, sent right after an owner stock update and by `flask send-stock-alerts` every 5 minutes; migration `5e1b8d3f7a92` (`stock_alerts`); white backgrounds with one green gradient for buttons.
- **Marketplace comparison update (9 Nov):** compared with Amazon, Flipkart, BigBasket and Blinkit (see docs/FEATURES-AND-DESIGN.md); added star-by-star rating bars, a Share button, a trust strip, quick "Add to cart" on product cards, and a helpful empty-search result with category links and "Ask us on WhatsApp".

## Phases 1–5

**Phase 5 — health, logging, security, push.** Public `GET /health` (database check plus version), JSON structured logs with request IDs and rotating files, stronger response headers, persistent per-account and per-IP login lockout (`login_lockouts`, HMAC-hashed identifiers), GitHub Actions CI, PostgreSQL backup tooling (`scripts/backup_postgres.sh`, `deploy/crontab.txt`), and opt-in Web Push (`push_subscriptions`, `/push/vapid-public-key`, subscribe and unsubscribe routes). Migration `5d2e9a7c1f40` merges all previous heads. Startup fixes: `requirements.txt` had literal `\n` text that broke `pywebpush`, a function-local `import logging` shadowed the module import (`UnboundLocalError`), and the merge migration now lists the real branch heads.

**Phase 4 — sales insights and inventory intelligence.** Repeat-customer rate, coupon usage, pincode sales, slowest products, `GET /owner/analytics.csv`; `products.reorder_level`; `inventory_batches` (batch number, expiry, quantity); expiring-in-30-days and days-of-stock-left panels. Batch quantity is traceability metadata and never silently changes sellable stock. Migration `1c4f8a9d2b70`.

**Phases 2 and 3 — foundations.** Owner WhatsApp status messages (English and Tamil defaults, editable templates, history and audit entries); share helper (Web Share API, clipboard, `wa.me`); referral code field and card; points ledger, search-term and recipe-favourite tables; Tamil fields and preferred-language setting; gift message and hide-prices at checkout (hide-prices invoices print as a price-free packing slip); recipe cook mode with optional Wake Lock. Referral attribution, loyalty earn and redeem, full Tamil translation, structured recipe steps, review photo moderation and restock reminders were **not** completed. Migration `aa71c4e9d302`.

**Phase 1 — order experience.** Frequently bought together and cart suggestions (co-purchase ranking over distinct orders, six-hour in-process cache, same-category fallback); courier name, tracking id and HTTPS-only tracking URL on orders with audit entries and a customer timeline (Placed, Confirmed, Packed, Shipped, Out for delivery, Delivered, plus terminal states); delivery slots with cutoff, capacity, blocked dates and horizon, validated again on the server under a row lock; saved pincode and address memory; delivery fee always comes from the delivery zone (the old free-delivery threshold was removed). Migration `7a91c3e5d802`.
