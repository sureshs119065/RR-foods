## Unreleased - Step 5.5-5.6 Security: upload hardening, cross-user authorization tests

**5.5 Uploads**
- **What was already right (kept, now pinned by tests):** the type is decided by opening the file with Pillow, never by extension or the browser's MIME type; every image is re-encoded to WebP, so a script appended to a real image does not survive; names are `uuid4().hex`; images over 5 MB and videos over 50 MB are refused; SVG, GIF, BMP, TIFF, ICO and PDF are refused.
- **EXIF / GPS / XMP / PNG text chunks:** verified on the stored bytes (a JPEG with a camera make, a GPS block and a comment goes in; none of it is in the main file, the 400 px or the 800 px copy). The EXIF rotation is applied before the tag is dropped, so sideways phone photos come out upright.
- **Decoders limited:** `Image.open(..., formats=("JPEG","PNG","WEBP"))`, so no other format parser ever sees an upload.
- **Pixel cap from the header:** a 49-megapixel PNG that is only a few KB on disk was only a Pillow *warning* (the error starts at twice the limit) and was then decoded. It is now refused before any pixel is decoded (`MAX_PIXELS`, 40 MP).
- **File names in error messages:** the visitor's file name was echoed back unchanged (any length, control characters). It is now reduced to its last path part, printable characters only, 40 characters.
- **No execute bit:** every written file (images, 400/800 px copies, banners, videos) is `chmod 0644`.
- **`/uploads/` serves a fixed list only** (`.webp .jpg .jpeg .png .mp4 .webm .mov`) with a Content-Type from a table, not guessed from the name. Anything else (`.html`, `.svg`, `.php`, `.js`, no extension, dotfiles, `evil.webp.html`) is a 404 even if somebody manages to put it in the folder. Responses also carry `nosniff`, `Content-Disposition: inline` and `Content-Security-Policy: default-src 'none'; sandbox`.
- **Customer requests are capped at 16 MB** (`CUSTOMER_MAX_UPLOAD_MB`; three 5 MB review photos plus fields). `/admin` and `/owner` keep `MAX_UPLOAD_MB` (60). Over the cap is a 413 with a normal error page. The cap is set in a hook registered *before* `csrf.init_app`, because the CSRF check reads the form: after it, the cap would never apply (a test fails if the order changes).
- **`flask check-config`:** `UPLOAD_DIR` inside the app folder (code, templates, static) is now fatal in production.
- **Not done, on purpose:** video metadata (GPS in MP4/MOV atoms) cannot be stripped without ffmpeg; videos are admin-only uploads. Malware scanning is not added (no scanner in the stack); re-encoding images removes any payload that is not pixels.

- **Staff routes:** with real ids (an order, a product, a user, a coupon, a review) customers get 403 on 23 admin and owner URLs, the owner gets 403 on admin URLs, the admin gets 403 on owner URLs, signed-out visitors are redirected, and the order, product, user, review and coupon rows are compared before and after.
