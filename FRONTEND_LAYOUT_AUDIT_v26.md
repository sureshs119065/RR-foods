# RR FOODS v25 layout audit and v26 replacement

## v25 audit scope

Inspected the shared base template, storefront layout, home template, Offers template, shared carousel partial, all storefront CSS layers, and the shared shell JavaScript. The CSS declaration inventory below records each v25 selector in the six stylesheets that controlled width, max/min-width, horizontal/vertical padding, margins, gaps, grid columns, overflow and box sizing. Responsive declarations are included with their media-query context.

## Findings

- The layout was spread across `base.css`, `shop.css`, `rr-foods-design.css`, `rr-foods-white-ui.css`, `rr-foods-overrides.css`, and the very large `rr-foods-mobile-fix.css`.
- The audit found 5 `!important` layout-related declarations in `base.css`, 13 in `shop.css`, 326 in `rr-foods-design.css`, 80 in `rr-foods-white-ui.css`, none in `rr-foods-overrides.css`, and 4,109 in `rr-foods-mobile-fix.css`.
- Multiple `.container`, header, hero, shelf, carousel, and breakpoint rules competed. The mobile-fix layer was especially large and append-only, so later declarations could override earlier desktop and mobile geometry.
- `shop/layout.html` had its own header/footer shell while pages extending `base.html` could use a different shell. The home hero's copy was not constrained by the same `.container` as the section content.
- The Offers route passed the home-page `rows=storefront.home_rows()` result although `offers.html` does not use `rows`. That introduced unrelated homepage catalogue/database work into the Offers request path. The v26 route now supplies only the data actually used by the template. This removes the unnecessary failure surface; the exact original production traceback was not available in the supplied ZIP, so the historic 500's precise runtime exception cannot be conclusively named from the archive alone.

## v26 replacement

- Added `app/static/css/rr-storefront-layout.css` as the single storefront geometry layer, with the requested `--container-max`, `--gutter`, `--section-gap`, `--radius`, brand colours, global box sizing and overflow clipping.
- Header, hero copy, storefront sections, Offers, and footer now use the same `.container`.
- Replaced the two-row header with one desktop grid row and a mobile hamburger/search pattern. The cart uses inline SVG and a visible green circular action.
- Product shelves and category tiles use equal-height grid tracks at desktop/tablet/mobile widths; product add-to-cart actions are pinned to the bottom.
- Removed `rr-foods-design.css` and `rr-foods-white-ui.css` from the public `base.html` cascade to stop their important declarations overriding the new system. Admin/owner layouts retain their own styling links.
- Replaced the old `rr-foods-mobile-fix.css` contents with a compatibility note; it is no longer linked by the storefront.
- Added shared `storefront_header.html` and `storefront_footer.html` partials and wired them into the base and storefront layouts.
- No JavaScript file was changed; the existing `shop.js` already handles the `[data-open]`, `[data-close]`, drawer, search overlay, and `[data-suggest]` hooks used by the revised header.

## Verification performed

- All Jinja templates compile when the application's registered `local_display` and `ago` filters are stubbed for syntax validation.
- The modified Python route module compiles.
- All CSS files parse without syntax errors.
- A live Flask request test could not run in this environment because Flask is not installed in the execution runtime. The supplied project itself includes Flask in `requirements.txt`; after installing dependencies and configuring the database, verify `/offers` and the listed viewport widths in a browser.
